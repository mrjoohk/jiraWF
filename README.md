# jiraWF — Jira 개인 업무 기록·추적 순환

Jira에서 내 태스크를 가져와 로컬에 일일 업무 기록을 만들고, 하루가 끝나면 진행 메모를 Jira 코멘트·하위 티켓으로 되돌리는 **개인용** 워크플로우입니다.

```
13:00 일일 배치 ──▶ daily/YYMMDD.md ──▶ (하루 작업, 진행 메모 기입)
      ▲                                          │
      │                                          ▼
   Jira Cloud ◀────── 마감 (승인 후 반영) ◀──────┘
      │
      └──▶ 금요일 주간 롤업 ──▶ weekly/YYWww.md
```

루프는 **마감 → Jira → 다음 날 배치** 경로로 닫힙니다. 마감을 하지 않은 날은 Jira에 변동이 없으므로 기록에도 남지 않습니다(배치가 이를 감지해 경고합니다).

## 설치

### 1. Atlassian 커넥터 연결
각자 자기 계정으로 연결합니다. **인증 정보는 배포되지 않습니다.**
Claude 앱의 커넥터 설정에서 Atlassian을 연결하십시오.

### 2. 플러그인 설치
```
/plugin marketplace add mrjoohk/jiraWF
/plugin install jira-worklog
```

### 3. 초기화
```
/wf-init
```
작업 폴더, 범위(프로젝트 키 + 선택적 에픽), 프로젝트 유형 판별, 예약 작업 등록까지 한 번에 처리합니다.
**여러 번 실행해도 기존 기록은 지워지지 않습니다.**

## 작업 폴더는 여러 개 둘 수 있습니다

폴더 하나가 범위 하나를 맡습니다. 범위는 **프로젝트 키 1개 + 에픽(선택) + 제목 필터(선택)**입니다.

```
~/work-a   →  프로젝트 XXX 전체
~/work-b   →  프로젝트 XXX 중 에픽 XXX-100 만
~/work-c   →  에픽 XXX-100 중 제목에 "[C]"가 있는 것만   (title_include)
~/work-d   →  에픽 XXX-100 중 나머지                      (title_exclude)
```

에픽 하나를 두 폴더가 나눠 맡을 때는 제목으로 가릅니다. **한쪽은 `title_include`, 다른 쪽은 같은 패턴의 `title_exclude`**로 두십시오. 양쪽 다 `title_include`를 쓰면 어느 패턴에도 안 걸리는 제목이 어느 폴더에도 안 잡히고, 그 사실이 아무 데도 남지 않습니다. 배치는 매번 "제목 필터로 빠진 키"를 알려주니 대조하십시오.

각 폴더는 자기 `state.json`·`daily/`·태스크 번호를 따로 갖습니다. 같은 프로젝트를 여러 폴더로 나눌 때는 **에픽으로 겹치지 않게 갈라야 합니다** — 범위가 겹치면 두 폴더가 같은 태스크에 하위 티켓을 각각 만듭니다. 겹친 채로 배치가 돌면 `INV-5`가 멈춰 세웁니다.

플러그인은 폴더 목록을 갖고 있지 않으므로, 폴더가 둘 이상이면 스킬을 실행할 때 **어느 폴더인지 알려주십시오.**

## 사용

| 명령 | 시점 | 하는 일 |
|---|---|---|
| `일일 배치` (worklog-daily) | 평일 13:00 예약 | Jira 변동 수집 → `daily/YYMMDD.md` 갱신 |
| `마감` (worklog-close) | 하루 작업 후 수동 | 진행 메모 → Jira 코멘트·하위 티켓 (**승인 후**) |
| `주간일지` (worklog-weekly) | 금요일 예약 | 그 주 daily → `weekly/YYWww.md` |

하루 흐름은 이렇습니다.

1. 13시에 배치가 돌아 `daily/YYMMDD.md`가 갱신됩니다.
2. 그 파일을 보며 작업하고, **진행 메모** 구획에 메모를 남깁니다.
   - `- [신규] 빌드 스크립트 정리` → **Jira에 없던 일을 새 메인 태스크로**
   - `- [파생] 회귀 시험 추가` → 하위 티켓 후보
   - `- [BUG] 좌표 변환 단위 오류` → 버그 하위 티켓 후보
   - 그 외 줄 → 해당 태스크의 진행 코멘트 재료
3. 일과 후 마감을 실행하면 초안이 나오고, **승인한 것만** Jira에 올라갑니다.

## Jira 구조 전제

```
과제 (Epic)  →  메인 태스크 (나에게 할당)  →  파생 (Sub-task, 버그 포함)
```

Jira Cloud 기본 계층 3단을 전부 씁니다. Sub-task는 자식을 가질 수 없으므로 **파생 작업 중 나온 새 항목은 메인 태스크 밑으로 평평하게** 붙습니다.

버그도 Sub-task로 만듭니다. 그래서 스프린트 보드에 독립 카드로는 보이지 않습니다 — 의도된 선택입니다.

## ⚠ 이 저장소는 public입니다

**업무 데이터를 이 저장소에 두지 마십시오.** `daily/`, `weekly/`, `state.json` 등은 `wf-init`가 지정한 별도 작업 폴더에 생성되며, 저장소 트리 안에 두려고 하면 `wf-init`가 거부합니다.

`.gitignore`와 CI 검사(`guard.yml`)가 2·3차 방어이지만, **1차 방어는 폴더를 분리해 두는 것**입니다.

## 문제가 생기면

| 증상 | 확인 |
|---|---|
| 배치가 "schema_version 불일치"로 멈춤 | 플러그인을 업데이트했습니다. 마이그레이션 안내를 따르십시오 |
| 조회 결과 0건 | 프로젝트 키, 에픽 키, Jira 권한, `assignee = currentUser()` 조건. 집계 출력의 `field_paths_used.issue_list`가 `<none>`이면 응답에서 이슈 배열을 못 찾은 것입니다 |
| `INV-5` 위반 | 이 폴더의 범위 밖을 수집했습니다. 조회 JQL에 에픽 필터가 빠졌는지 보십시오 |
| 태스크가 어느 폴더에도 안 나온다 | 제목 규약을 안 지킨 제목입니다. 배치 출력의 "제목 필터로 빠진 키"와 대조하십시오 |
| 집계가 exit 2로 멈춤 | `title_include`/`title_exclude`의 정규식이 잘못됐습니다. 메시지에 문제 패턴이 찍힙니다 |
| 마감이 "이 폴더가 맡지 못할 제목" 으로 멈춤 | `title_prefix`가 비었거나 필터와 안 맞습니다. 그대로 만들면 티켓이 일지에서 사라지므로 막습니다 |
| 일지에 이상한 이슈 키 | `INV-4` 검사가 잡습니다. `logs/*/evidence.json`을 보십시오 |
| 진행 메모가 사라졌다 | 발생하면 안 되는 일입니다. `INV-1` 위반이므로 이슈로 올려 주십시오 |

설계 배경과 "하지 않는 것"은 [DESIGN.md](DESIGN.md)에 있습니다.
