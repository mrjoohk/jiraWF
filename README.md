# jiraWF — Jira 개인 업무 기록·추적 순환

Jira에서 내 태스크를 가져와 로컬에 일일 업무 기록을 만들고, 하루가 끝나면 진행 메모를 Jira 코멘트·티켓으로 되돌리는 **개인용** 워크플로우입니다.

```
13:00 일일 배치 ──▶ daily/YYMMDD.md ──▶ (하루 작업, 진행 메모 기입)
      ▲                                          │
      │                                          ▼
   Jira Cloud ◀────── 마감 (승인 후 반영) ◀──────┘
      │
      └──▶ 금요일 주간 롤업 ──▶ weekly/YYWww.md
```

루프는 **마감 → Jira → 다음 날 배치** 경로로 닫힙니다. 마감을 하지 않은 날은 Jira에 변동이 없으므로 기록에도 남지 않습니다(배치가 이를 감지해 경고합니다).

> 이 문서는 **쓰는 사람**을 위한 매뉴얼입니다. 설치·초기화를 대신 해 주는 에이전트용 절차서는 [AGENTS.md](AGENTS.md)에, 설계 배경과 "하지 않는 것"은 [DESIGN.md](DESIGN.md)에 있습니다.

## 1. 설치

### 1-1. Atlassian 커넥터 연결
Claude 앱의 커넥터 설정에서 Atlassian을 연결합니다. **각자 자기 계정으로 연결해야 합니다** — 인증 정보는 플러그인에 담겨 배포되지 않습니다.

### 1-2. 플러그인 설치
```
/plugin marketplace add mrjoohk/jiraWF
/plugin install jira-worklog
```

### 1-3. 초기화
```
/wf-init
```
작업 폴더, 범위(프로젝트 키 + 에픽 + 제목 규약), 프로젝트 유형 판별, 예약 작업 등록까지 한 번에 처리합니다. **여러 번 실행해도 기존 기록은 지워지지 않습니다** — 뭔가 이상할 때 다시 돌려도 안전합니다.

작업 폴더를 여러 개 쓸 거라면 **폴더마다 한 번씩** 돌립니다.

## 2. 작업 폴더와 범위

폴더 하나가 범위 하나를 맡습니다. 범위는 **프로젝트 키 1개 + 에픽(선택) + 제목 필터(선택)**입니다.

```
~/work-a   →  프로젝트 XXX 전체
~/work-b   →  프로젝트 XXX 중 에픽 XXX-100 만
~/work-c   →  에픽 XXX-100 중 제목에 [C] 가 있는 것만   (title_include)
~/work-d   →  에픽 XXX-100 중 나머지                     (title_exclude)
```

각 폴더는 자기 `state.json`·`daily/`·태스크 번호를 따로 갖습니다. 폴더를 늘리는 비용은 거의 없습니다.

### 겹치면 안 됩니다
두 폴더가 같은 태스크를 보면 각자 번호를 매기고 각자 하위 티켓을 만듭니다. 마감이 "이미 만든 것은 다시 안 만든다"를 판단할 때 **자기 폴더 기록만 보기 때문에** 상대가 만든 것을 알지 못합니다. 겹친 채로 배치가 돌면 `INV-5`가 멈춰 세웁니다.

### 에픽 하나를 둘로 나눌 때
제목 규약으로 가릅니다. 예를 들어 제목 앞에 `[A]` / `[B]`를 붙이기로 정하고, 한 폴더는 `[A]`를 맡고 다른 폴더는 나머지를 맡습니다.

**양쪽 다 "포함" 조건만 쓰면 위험합니다.** 어느 패턴에도 안 걸리는 제목이 생기면 그 태스크는 **어느 폴더에도 안 잡히고, 그 사실이 아무 데도 남지 않습니다.** 한쪽을 "제외" 조건으로 두어 나머지를 받게 하면 둘이 합쳐 빠짐없이 덮습니다.

포함 조건만 쓰기로 했다면, 배치가 매번 알려주는 **"제목 필터로 빠진 키"**를 대조하십시오.

### 폴더가 둘 이상이면
플러그인은 폴더 목록을 갖고 있지 않습니다(의도된 설계 — [DESIGN.md](DESIGN.md) 참고). 그래서 스킬을 실행할 때 **어느 폴더인지 알려주셔야 합니다.**

## 3. 무슨 말을 하면 되나

명령은 셋뿐입니다. **아래 문구 중 아무거나 말하면 걸립니다.**

| 하고 싶은 것 | 이렇게 말하면 됩니다 | 하는 일 |
|---|---|---|
| 오늘 할 일 받아오기 | `일일 배치` · `오늘 할 일 가져와` · `업무일지 갱신` | Jira 변동 수집 → `daily/YYMMDD.md` 갱신 |
| 오늘 한 일 Jira에 올리기 | `오늘 한 일 정리해줘` · `마감` · `오늘 정리` · `Jira에 올려줘` | 진행 메모 → 코멘트·티켓 (**승인 후**) |
| 주간일지 만들기 | `주간일지` · `이번 주 정리` · `주간 롤업` | 그 주 daily → `weekly/YYWww.md` |

**작업 폴더가 둘 이상이면 어느 폴더인지 함께 말해야 합니다.** 플러그인은 폴더 목록을 갖고 있지 않습니다.

> "PFD 쪽 오늘 한 일 정리해줘"

## 4. 하루 시퀀스

### 4-1. 아침 — 오늘 할 일 받아오기

```
나: 일일 배치 돌려줘
```

평일 13:00 예약을 걸어 뒀다면 이건 저절로 돌아가므로 말할 필요가 없습니다. 예약을 안 걸었거나 그날 실행이 빠졌으면 직접 부릅니다. **빠진 날이 있어도 다음 실행이 그 구간을 흡수합니다** — 전날이 아니라 마지막 성공 시각을 기준으로 가져오기 때문입니다.

결과는 이렇게 나옵니다.

```
신규 2 / 이어서 3 / 정체 1 · 미등록 파생 0건
daily/260827.md
```

`daily/260827.md`에 **과제(에픽)별로 묶인 오늘 할 일**이 들어 있습니다.

### 4-2. 낮 — 일하면서 기록

두 가지 방법이 있고, 섞어 써도 됩니다.

**(a) 파일에 직접 적기** — `daily/260827.md`를 열어 `## 진행 메모` 구획에 씁니다.

```markdown
<!-- MEMO:START -->
- 케이블 규격 확인하고 발주서 초안 넘김
- [파생] 커넥터 핀맵 재확인 필요
- [신규] 시험환경 랙 배치도 갱신
<!-- MEMO:END -->
```

**(b) 말로 알려주기** — 마감할 때 그냥 말하면 메모 구획에 받아 적습니다.

```
나: 오늘 한 일 정리해줘. 케이블 규격 확인해서 발주서 초안 넘겼고,
    커넥터 핀맵은 다시 봐야 할 것 같아. 그리고 시험환경 랙 배치도를 새로 그렸어.

에이전트: 메모에 이렇게 적었습니다. 맞습니까?
    - 케이블 규격 확인하고 발주서 초안 넘김
    - 커넥터 핀맵 재확인 필요
    - 시험환경 랙 배치도 갱신
```

**받아쓰기이지 대신 써 주는 것이 아닙니다.** 말한 것만 옮기고, "그러면 이것도 했겠네" 같은 보충은 하지 않습니다. 적은 내용을 보여 주고 확인받은 뒤에 다음으로 넘어갑니다 — 메모가 곧 초안의 입력이라 여기서 틀리면 뒤의 승인 화면은 이미 틀린 것을 보여 줄 뿐입니다.

메모에 아무것도 없고 말해 준 것도 없으면 마감은 **그냥 끝납니다.** 없는 것을 지어내지 않습니다.

### 4-3. 저녁 — 마감

```
나: 오늘 한 일 정리해줘
```

메모를 읽어 초안을 만들고 **표로 보여 줍니다.** 여기서부터가 핵심입니다.

```
[기존 태스크에 붙일 것]
  R-002 (XXX-113) 통합 시험환경 설계
      코멘트: 케이블 규격 확인, 발주서 초안 전달. 핀맵 확인이 남음.
      └ 파생 신규: 커넥터 핀맵 재확인

[Jira에 없는 것 — 어떻게 할까요?]
  N-1  시험환경 랙 배치도 갱신
       (1) 새 태스크로 만들기 → "[PFD] 시험환경 랙 배치도 갱신"
       (2) 기존 태스크에 병합
       (3) 보류
```

**(1)을 고르면** 에픽 아래에 새 태스크가 생깁니다. 제목 규약이 있으면 접두사가 자동으로 붙습니다.

**(2)를 고르면** 에픽 안의 내 태스크를 번호로 보여 줍니다.

```
  #  키          범위  상태     제목
  1  XXX-113     안   진행 중   통합 시험환경 설계
  2  XXX-114     안   진행 중   케이블류 구매
  3  XXX-098     안   완료      랙 도면 1차
  4  XXX-201     밖   해야 할 일 데이터링크 회의
```

`범위`가 **`밖`**이면 이 폴더가 맡지 않는 태스크입니다. 고를 수는 있지만 코멘트만 남고 **이 폴더의 일지에는 안 나타납니다.** `완료`된 태스크도 고를 수 있지만 다음 배치의 미완료 조회에는 안 잡힙니다. 둘 다 고르기 전에 알려 줍니다.

**(3)을 고르면** 메모에 그대로 남아 다음 마감에 다시 올라옵니다. 조용히 사라지지 않습니다.

승인한 것만 Jira에 올라가고, 처리된 메모 줄에는 `✓ XXX-115`가 붙습니다. **상태 전이는 하지 않습니다** — 완료 처리는 Jira에서 직접 하십시오.

### 4-4. 금요일 — 주간일지

```
나: 이번 주 정리해줘
```

그 주 `daily/*.md`를 모아 `weekly/26W35.md`를 만듭니다. **daily에 없는 내용은 쓰지 않습니다.** 빠진 날이 있으면 그 사실을 일지에 명시합니다(휴가인지 실행 누락인지는 사람이 판단할 몫입니다).

## 5. 자주 겪는 경우

**어제 마감을 깜빡했습니다** — 오늘 배치가 "어제 마감 누락 의심"을 표시합니다. 어제 `daily` 파일의 메모는 그대로 있으니, 어제 날짜로 마감하면 됩니다.

**메모에 표시를 안 붙였습니다** — 괜찮습니다. 어느 기존 태스크에도 안 붙는 줄은 신규 후보로 올라오고, 판단이 안 서는 줄은 원문 그대로 보여 줍니다.

**초안이 엉뚱한 태스크에 붙였습니다** — 승인 화면에서 (2) 병합을 골라 올바른 번호를 지정하면 됩니다. 초안은 제안일 뿐이고 **고르는 것은 사람입니다.**

**같은 일을 두 폴더에서 마감했습니다** — 같은 태스크에 하위 티켓이 두 번 생깁니다. 마감 전 사전 확인이 범위 어긋남을 잡지만, 두 폴더가 **같은 범위**를 맡고 있으면 못 잡습니다. 마감은 한 폴더에서만 하십시오.

**어제 만든 태스크가 오늘 안 보입니다** — 제목 규약을 지켰는지 보십시오. 배치가 "제목 필터로 빠진 키"를 알려 줍니다.

## 6. Jira 구조 전제

```
과제 (Epic)  →  메인 태스크 (나에게 할당)  →  파생 (Sub-task, 버그 포함)
```

Jira Cloud 기본 계층 3단을 전부 씁니다. Sub-task는 자식을 가질 수 없으므로 **파생 작업 중 나온 새 항목은 메인 태스크 밑으로 평평하게** 붙고, 계보는 코멘트로 남습니다.

버그도 Sub-task로 만듭니다. 그래서 스프린트 보드에 독립 카드로는 보이지 않습니다 — 의도된 선택입니다.

---

## 7. ⚠ 이 저장소는 public입니다

**업무 데이터를 이 저장소에 두지 마십시오.** `daily/`, `weekly/`, `state.json` 등은 `wf-init`가 지정한 별도 작업 폴더에 생성되며, 저장소 트리 안의 경로를 지정하면 `wf-init`가 거부합니다.

`.gitignore`와 CI 검사(`guard.yml`)가 2·3차 방어이지만, **1차 방어는 폴더를 분리해 두는 것**입니다.

## 8. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 조회 결과 0건 | 프로젝트 키·에픽 키·Jira 권한. 제목 필터를 쓴다면 접두사 규약을 지킨 태스크가 있는지. 배치 출력의 `field_paths_used.issue_list`가 `<none>`이면 응답에서 이슈 배열을 못 찾은 것입니다 |
| 태스크가 어느 폴더에도 안 나온다 | 제목 규약을 안 지킨 제목입니다. 배치가 알려주는 "제목 필터로 빠진 키"와 대조하십시오 |
| 배치가 `schema_version 불일치`로 멈춤 | 플러그인을 업데이트했습니다. `/wf-init`을 다시 돌리면 마이그레이션됩니다(기록은 보존) |
| `INV-5` 위반 | 이 폴더의 범위 밖을 수집했습니다. 그대로 마감하면 다른 폴더와 티켓이 중복되므로 막습니다 |
| 집계가 `exit 2`로 멈춤 | 제목 필터의 정규식이 잘못됐습니다. 메시지에 문제 패턴이 찍힙니다 |
| 마감이 "이 폴더가 맡지 못할 제목"으로 멈춤 | 접두사가 비었거나 필터와 안 맞습니다. 그대로 만들면 티켓이 일지에서 사라지므로 막습니다 |
| 일지에 이상한 이슈 키 | `INV-4`가 잡습니다. `logs/*/evidence.json`을 보십시오 |
| 진행 메모가 사라졌다 | 발생하면 안 되는 일입니다. `INV-1` 위반이므로 이슈로 올려 주십시오 |

배치가 실패하면 **watermark를 전진시키지 않습니다.** 다음 실행이 그 구간을 다시 가져가므로, 고친 뒤 다시 돌리면 빠진 기간이 메워집니다.
